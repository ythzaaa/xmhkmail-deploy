# xmhkmail 部署

公共部署仓库，只包含入口脚本、发布索引、部署包和 SHA256 校验文件。不包含应用源码、凭据或业务数据。

## 安装、更新与卸载

在装有 curl 的 Linux amd64 主机执行。服务器没有 Docker 时，安装会显示 Docker 官方 apt 源与签名密钥指纹，确认后自动安装 Docker Engine 和 Compose 插件；已有 Docker 不会被升级或改动：

```sh
curl -fsSL https://raw.githubusercontent.com/ythzaaa/xmhkmail-deploy/main/xmhkmail.sh | sudo bash
```

从菜单选择安装、更新、状态、停启、备份、恢复包、中断恢复、清理旧镜像或卸载。首次安装按向导填写邮件主机名和证书通知邮箱，公网 IPv4 可留空。

直接更新：

```sh
curl -fsSL https://raw.githubusercontent.com/ythzaaa/xmhkmail-deploy/main/xmhkmail.sh | sudo bash -s -- update
```

新部署状态保存在 `/var/lib/xmhkmail`。已有默认项目自动识别原目录；非默认项目追加 `--directory /原部署目录`。不要删除原部署目录。卸载仅移除本项目容器与网络，配置、密钥、备份、镜像和数据卷保留。

更新先验证发布包，再更新公共脚本与业务镜像；不覆盖配置或数据，不自动升级 PostgreSQL、Redis 或 Caddy。同版本、同运行镜像且健康时不重复停机。版本变更时自动执行离线加密备份和迁移检查，会暂停邮件与网页。

## 当前版本

本轮部署包为 `v0.1.0-rc.6-r5`，app、mail、backup 三张镜像均为公开 rc.6，使用同版本固定 SHA256 摘要。确认更新目标显示 rc.6 后继续；历史版本保留。r4、r5 只更新主机脚本：服务器完全没有 Docker 时，安装会显示官方 apt 源和签名密钥指纹，确认后安装 Docker，已有 Docker 不会被改动；版本更新成功后自动删除本部署更早版本的 app/mail/backup 镜像，只保留当前版本和上一版，也可在菜单选择“清理旧镜像”。已部署的服务器执行更新只会刷新脚本，不需要停机。

rc.6 的邮箱域名选择列表在选择框下方弹出，可搜索、分页并在选中后收起。账号与域名列表有删除确认：账号从正常列表移除、撤销 Web 登录与应用密码，但保留邮件、草稿、联系人、地址和配额，同名地址不可重建；域名仅允许停用且无关联时删除，不级联清空数据。

保留 rc.5-r2 的 CRLF 模板兼容修复。模板只因换行不同，不需要手工改文件或重装，直接使用上面的更新命令；真实端口、挂载、注释或其他改动仍会拒绝并显示待核对文件。私有配置、密钥、历史备份和失败记录保留。

rc.5 修复正常 Maildir 文件名导致升级备份验证失败的问题，并兼容 Compose 错误日志末尾的空行。更新仍由原工具创建全新离线备份；仅已知旧版本与已知错误允许使用目标固定摘要工具做完整只读验证，不跳过备份。此前已中止且旧服务恢复健康的更新，可用上面的命令重新开始；不删除旧失败记录或复用旧备份。其他错误需要检查实际日志，不能一概重试。

保留新账号默认禁发、Webmail 自动刷新，以及首次安装密码规则和恢复包下载。已有账号发信权限保留；新账号需要发信时在管理编辑页开启。主机工具自动准备备份密钥，已有密钥不会重新生成。rc.6 自动执行迁移 012；rc.3 升级也会执行已有迁移 011。迁移后旧 rc.5 或更早应用会拒绝新数据库，不能仅切旧镜像回退；保留原数据和备份，在独立空环境恢复。

支持 Debian 12/13、Ubuntu 24.04/26.04 的 Linux amd64 宿主。无人值守安装且服务器没有 Docker 时须加 `--install-docker`。不修改 DNS/防火墙、不探测公网 SMTP；容器健康不代表公网收发已经验收。详细说明随 Release 部署包提供。
